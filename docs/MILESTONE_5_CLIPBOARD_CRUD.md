## 1. Overview & Architecture

Milestone 5 implements the core clipboard management engine for SyncShelf. Building on the zero-trust security model established in Milestone 4, all clipboard mutations (creation, updates, deletions) are mediated exclusively by Next.js API route handlers using the Firebase Admin SDK. Direct client writes to Cloud Firestore remain strictly prohibited (`allow write: if false;`).

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        CLIENT LAYER (Browser)                          │
│  - QuickCaptureModal: Explicit clipboard paste via Web API             │
│  - ClipboardFeed: Filtering, cursor pagination, optimistic pin toggle  │
│  - ClipboardCard: Shiki code highlighting, link previews, tags         │
└───────────────────┬────────────────────────────────▲───────────────────┘
                    │ (Mutations: POST/PATCH/DELETE) │ (Direct Reads /
                    ▼                                │  Future onSnapshot)
┌──────────────────────────────────────────┐         │
│          NEXT.JS API ROUTE HANDLERS      │         │
│  - Bearer Token Auth (verifyAuthToken)   │         │
│  - RBAC Enforcement (canCreate/Edit/Del) │         │
│  - Zod Request Validation                │         │
│  - Server Timestamps & Computed Fields   │         │
└───────────────────┬──────────────────────┘         │
                    │ (Privileged Admin SDK)         │
                    ▼                                │
┌────────────────────────────────────────────────────┴───────────────────┐
│                     CLOUD FIRESTORE (Native Mode)                      │
│      Collection: workspaces/{workspaceId}/items/{itemId}               │
│      Rules: allow read: if isWorkspaceMember(workspaceId);             │
│             allow write: if false;                                     │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Firestore Data Model & Schema

All clipboard entries are stored in a dedicated subcollection under the tenant workspace:

`workspaces/{workspaceId}/items/{itemId}`

### Document Schema

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `string` | Unique document ID (generated by Firestore) |
| `workspaceId` | `string` | ID of the parent workspace |
| `type` | `"text" \| "code" \| "link"` | Content classification |
| `title` | `string` | Short human-readable title (1–100 characters) |
| `content` | `string` | Raw payload (1–50,000 characters) |
| `language` | `string?` | Optional language identifier for code items (e.g., `typescript`, `python`, `json`) |
| `tags` | `string[]` | Array of up to 10 tags (1–30 characters each, trimmed) |
| `isPinned` | `boolean` | Pinned status for quick access (defaults to `false`) |
| `contentLength`| `number` | Byte/character length computed on the server (`content.length`) |
| `createdBy` | `string` | Firebase UID of the author (derived strictly from auth token) |
| `createdAt` | `Timestamp` | Server timestamp set at creation (`FieldValue.serverTimestamp()`) |
| `updatedAt` | `Timestamp` | Server timestamp set on creation and updated on every mutation |

### Schema Validation (`src/lib/validation/item.ts`)

Incoming payloads are validated with Zod before any Firestore operation:
- **`createItemSchema`**: Validates mandatory `type`, `title`, and `content`, enforcing length bounds and trimming tags.
- **`updateItemSchema`**: Validates partial updates to `title`, `content`, `type`, `language`, `tags`, and `isPinned`. Client modification of `createdBy`, `createdAt`, `workspaceId`, or `id` is stripped.
- **`listItemsQuerySchema`**: Validates query parameters (`limit` 1–50, `cursor`, `type`, `pinned`, `search`).

## 3. Server-Side RBAC & API Routes

All endpoints enforce cryptographic Bearer token verification via `verifyAuthToken()` and workspace role resolution via `getWorkspaceMemberRole()`.

### Role-Based Access Matrix

| Action | Owner | Editor | Viewer | Non-Member / Unauthenticated |
| :--- | :---: | :---: | :---: | :---: |
| **List / Read Items** (`GET`) | Allowed | Allowed | Allowed | Denied (`401` / `403`) |
| **Create Item** (`POST`) | Allowed | Allowed | Denied (`403`) | Denied (`401` / `403`) |
| **Update Item** (`PATCH`) | Allowed | Allowed | Denied (`403`) | Denied (`401` / `403`) |
| **Delete Item** (`DELETE`) | Allowed | Allowed | Denied (`403`) | Denied (`401` / `403`) |

### API Implementation Details

1. **`GET /api/workspaces/[workspaceId]/items`**:
   - Queries `workspaces/{workspaceId}/items` ordered by `createdAt desc`.
   - Supports query filters: `?type=text|code|link` and `?pinned=true`.
   - Implements Firestore document-snapshot cursor pagination (`?cursor=<itemId>&limit=20`), returning `{ items, nextCursor, hasMore }`.
   - Supports search filtering across item `title`, `content`, and `tags`.

2. **`POST /api/workspaces/[workspaceId]/items`**:
   - Verifies `canCreateItem(role)`.
   - Assigns `createdBy: user.uid` to prevent identity spoofing.
   - Computes `contentLength: content.length`.
   - Writes document using Admin SDK with server timestamps. Returns HTTP `201 Created`.

3. **`PATCH /api/workspaces/[workspaceId]/items/[itemId]`**:
   - Verifies `canEditItem(role)`.
   - Confirms the item exists in the specified workspace (returns `404` if not found).
   - Updates allowed fields and sets `updatedAt: FieldValue.serverTimestamp()`.
   - Recomputes `contentLength` if `content` is updated. Returns HTTP `200 OK`.

4. **`DELETE /api/workspaces/[workspaceId]/items/[itemId]`**:
   - Verifies `canDeleteItem(role)`.
   - Confirms the item exists in the specified workspace (returns `404` if not found).
   - Deletes the document via Admin SDK. Returns HTTP `200 OK`.

## 4. UI Components Built

1. **`CodeBlock` (`src/components/ui/code-block.tsx`)**:
   - Syntax highlighting powered by `shiki` with the `github-dark` theme.
   - Dynamic ESM import for zero SSR hydration flicker.
   - One-click copy-to-clipboard button with visual checkmark confirmation.
   - Language badge and line number styling.

2. **`ClipboardCard` (`src/features/clipboard/clipboard-card.tsx`)**:
   - Visual differentiation by item type (Text, Code, Link).
   - Code snippet preview with expandable line limit.
   - Link items display cleaned destination hostname and open in an external tab with secure `rel="noopener noreferrer"`.
   - Tag pills with overflow handling.
   - Action toolbar: Quick copy, Pin toggle, Edit modal trigger, Delete dialog trigger (actions hidden/disabled for Viewers).

3. **`QuickCaptureModal` (`src/features/clipboard/quick-capture-modal.tsx`)**:
   - Tabbed creation interface for Text, Code, and Link.
   - **Explicit Browser Clipboard Paste**: Uses `navigator.clipboard.readText()` via an explicit button click. Automatically selects content type (detects URLs for Links, code syntax for Code).
   - Syntax language dropdown selector for code snippets.
   - Dynamic tag input with keyboard chip creation.
   - Pin checkbox for immediate prioritization.

4. **`EditItemModal` & `DeleteItemDialog` (`src/features/clipboard/`)**:
   - Seamless editing of existing item title, content, type, language, and tags.
   - Destructive confirmation dialog before removing items.

5. **`ClipboardFeed` (`src/features/clipboard/clipboard-feed.tsx`)**:
   - Real-time search query input.
   - Category filtering tabs: `All`, `Text`, `Code`, `Links`, `Pinned`.
   - Cursor-based "Load More Items" button.
   - Optimistic pin state updates for snappy user experience.
   - Skeleton loading placeholders and error retry states.
